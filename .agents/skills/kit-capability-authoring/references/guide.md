# Capability resource and ownership contract

## Progressive disclosure

Discovery metadata identifies a task; it is not a compressed handbook.
The skill body gives the procedure and chooses references. References carry
decision tables, failure cases, quality gates and primary sources. Assets
provide usable templates or deterministic checks, not decorative empty folders.

Every canonical toolkit skill has a linked reference and usable asset.
The resource gate checks their presence, containment, discoverability and
structured-template/Python syntax. This is a structural minimum, not a
semantic completeness score or a provenance certification.

## Quality gates

- Extend the existing audience owner before adding another skill/role.
- Use exact minimal metadata and a task-specific description beginning "Use when".
- Keep all catalog budgets unchanged; select fewer skills when needed.
- Validate source links and installed relocation with real APM delivery.
- Retain a runnable regression for each new parser or validation rule.
- Any checker documents accepted input schema, failure exit and limitations.
- Keep company facts, upstream bodies and unverified licenses out of bundles.

## Failure and recovery

An asset that duplicates existing source is drift waiting to happen. Link or
render from the owner. Native role files share procedure bodies but retain
provider-specific fields. Audit owned output before any projection refresh,
then rerun role and drift checks. Never raise a budget or weaken provenance
to make newly added material pass.
