# Adopt without erasing the existing setup

## Inventory and selection

Record repository, parent, user and plugin capabilities for each intended host.
Compare names, effective scopes, tool exposure and owned outputs. Preserve
consumer facts, application guards, private knowledge and independently owned
files. A smaller package is not isolation from parent/global context.

Compose the real stack plus only needed optional bundles into a new path.
Inspect selection and provenance before running the pinned APM version.
Use task-level skill selection for short sessions; role projections are
intentionally absent from those deliveries.

## Quality gates

- Existing deployment/provenance is audited before regeneration.
- Selected source contains referenced resources and only approved role metadata.
- Real frozen install/compile is exercised in a disposable package.
- Consumer facts, knowledge links and app quality gates are filled and run locally.
- Native discovery, read-only denials, hooks and tool selection are tested in
  each exact host/version; file tests are not a substitute.
- Integrations require a separate endpoint/package, authentication, toolset,
  policy and startup review. Empty active MCP is a deliberate default.

## Failure and rollback

If installation would overwrite independently owned output, stop and resolve
ownership instead of forcing it. Keep previous revision, lock, manifest and
native settings. Roll back through the operator's reviewed workflow; do not
delete unknown files or change personal settings. Record unavailable native
checks and hosted protections as unverified.
