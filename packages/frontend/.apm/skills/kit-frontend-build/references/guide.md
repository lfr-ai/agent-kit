# Vite, Bun, and environment variables

Reviewed 2026-10-23 against Vite 8.3 (Rolldown bundler), Bun 1.4, and
Vitest documentation. Vite 8 renamed `build.rollupOptions` to
`build.rolldownOptions` and replaced object-form `manualChunks` with Rolldown
`codeSplitting` groups; older projects keep the Rollup names until upgraded.

## Vite configuration decisions

| Decision | Default choice | When to change |
| --- | --- | --- |
| Config files | `vite.config.ts` for app; `vitest.config.ts` merges it | Never fork build settings into test config |
| `build.target` | Vite default (`baseline-widely-available`) | Support matrix requires older browsers: set explicit targets and test them |
| Code splitting | Route-level `import()` | Measured cache or waterfall problem |
| Manual chunks | `build.rolldownOptions.output.codeSplitting.groups` | Stable vendor group improves repeat-visit cache hits |
| `build.sourcemap` | `"hidden"` when maps go to error tracking; `false` otherwise | Public maps are an explicit decision |
| `build.modulePreload` | Default polyfill on | Custom entries need `vite/modulepreload-polyfill` |
| `server.proxy` | Development only | Never a production routing mechanism |
| `preview` | `vite preview` against `dist` before release | Not a production server |
| `base` | `/` or the deployed sub-path | Set from configuration when hosted under a prefix |

### Code splitting with care

- Start from automatic splitting plus `lazy()` routes. Each manual group can
  pull shared modules forward and lengthen the critical path.
- Group by change frequency (framework, large vendor, app), not by package
  count. Keep the group set small and stable.
- After any change, compare the entry chunk size, the number of requests on
  first navigation, and the cache hit pattern across two deploys.
- Prefetching (`<link rel="modulepreload">`) is generated by Vite; do not hand
  write preload tags that bypass the manifest.

## Environment variables

| Rule | Detail |
| --- | --- |
| Public prefix | Only `VITE_*` (or `envPrefix`) reaches `import.meta.env` in client code |
| Everything public is published | Any `VITE_` value appears in shipped JavaScript; no secrets, tokens, or private hosts |
| Load order | `.env`, `.env.local`, `.env.[mode]`, `.env.[mode].local`; existing process variables win |
| Commit policy | Commit `.env.example` only; ignore `*.local` and real values |
| Types | Declare keys in `vite-env.d.ts` with `strictImportMetaEnv` (see `kit-runtime-config`) |
| Runtime versus build time | Prefer runtime `/config.json` for per-environment values so one artifact serves all environments |
| `define` | Only for compile-time constants such as a build id; never for secrets |

Names suggesting secrets (`VITE_API_KEY`, `VITE_CLIENT_SECRET`) are almost
always mistakes. Truly publishable identifiers (an OAuth public client id, a
browser analytics key designed to be public) stay allowed only with an explicit
`--allow` entry and a comment naming the provider documentation.

## Bun as package manager or runtime

| Question | Choose Bun when | Keep the existing tool when |
| --- | --- | --- |
| Package manager | Team agrees, `bun.lock` committed, CI uses `bun install --frozen-lockfile` | Another lockfile exists or tooling depends on it |
| Script runner | `bun run` for scripts already Node-compatible | Scripts rely on Node-only flags |
| Runtime for Vite and Vitest | Verified on the pinned versions in CI | Any unexplained divergence from Node results |
| Test runner | Vitest stays the runner; `bun test` is a different API | Always keep one test runner |

- One package manager per repository; delete stray lockfiles in the same
  change that adopts a manager.
- Pin the manager version (`packageManager` field or tool manifest) so local
  and CI installs resolve identically.
- Lifecycle scripts from dependencies run on install; review
  `trustedDependencies` instead of trusting everything.

## Failure modes

| Symptom | Cause | Repair |
| --- | --- | --- |
| `import.meta.env.X` undefined in the browser | Missing prefix or not set at build time | Prefix intentionally public values; use runtime config otherwise |
| Secret found in `dist` | Secret given a `VITE_` name or `define` | Move server-side; rotate the exposed value |
| Huge vendor chunk invalidated every deploy | One catch-all group including app code | Group by change frequency; verify hashes |
| Works in dev, fails in preview | Dev proxy or dev-only plugin masked a production gap | Test `vite build` plus `vite preview` |
| Different installs per machine | Floating manager version or mixed lockfiles | Pin manager; one lockfile; frozen installs |

## Verification

1. `bun install --frozen-lockfile` (or the declared manager's frozen mode).
2. Typecheck, lint, `vitest run`, `vite build`, then `vite preview` smoke.
3. `python check_frontend_env.py .` for public variable names.
4. Bundle scan from `kit-runtime-config` on `dist`, then budgets.
