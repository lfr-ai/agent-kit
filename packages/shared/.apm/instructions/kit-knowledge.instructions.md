description: Apply to consumer project facts, durable decisions and knowledge indexes.
applyTo: "PROJECT.md,projects.md,llms.txt,memories/**,.agents/knowledge-base/**"
---

- Keep consumer facts, private data and credentials out of portable packages.
- Link the authoritative command, code or test; separate observed facts from assumptions.
- Record only durable decisions with rationale, evidence, date and a relevant review trigger.
- Write one lesson per entry as a reusable rule, with the context in which it applies.
- Update or supersede an existing entry instead of adding a near-duplicate; link a superseded entry to its replacement.
- Do not treat session transcripts, guesses or one-off workarounds as durable policy.
- Remove facts that code, configuration or tests now state authoritatively, and link those sources instead.
- Keep entry indexes short and load detailed knowledge only for the current task.
- Never store tokens, connection strings, personal data or customer content, not even as redacted samples.
- Date time-sensitive facts such as versions and limits, and re-verify them before relying on them.
- Use the `kit-context-onboarding` skill to build or refresh project context.
