# Author one capability with progressive disclosure

## Choose the smallest owner

Extend a matching skill before adding a new trigger. Always-on safety belongs
in repository policy, narrow path invariants in instructions, task procedures
in a skill, and native tool/model fields in the runtime adapter.

Use a short discovery description that distinguishes this skill from neighbors.
Keep the procedure self-contained enough to select the next resource. Put
domain failure cases and quality gates in a reference, copyable output in an
asset, and deterministic repeated computation in a script only when useful.
Do not add an empty folder to satisfy a resource count.

## Resource contract

Link resources from the procedure. Keep paths relative and inside the package.
Scripts take explicit inputs, avoid importing consumer code, make no network
calls unless separately approved, and return a nonzero exit for malformed data.
Retain a runnable regression for branches/parsers. Templates must distinguish
placeholders from executable defaults and must not contain credentials.

## Quality gates

- Name matches directory; frontmatter fields follow the owning toolkit.
- The trigger selects this skill for a representative task, not every task.
- A normal case, invalid case and missing prerequisite have explicit outcomes.
- Resources resolve after composition and installation away from the checkout.
- Procedures do not claim that prompt text grants permission or isolation.
- License and source provenance permit public redistribution.

## Failure and recovery

If a resource duplicates another skill, link its owner and ensure the selected
profile includes it; do not rely on accidental parent discovery. If a procedure
requires an unavailable native feature, fail explicitly or document a reviewed
manual alternative, never silently simulate support.

Source: [Agent Skills specification](https://agentskills.io/specification).
